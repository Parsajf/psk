# وب‌سایت پاک سرا کارن — نسخهٔ Django

قالب اصلی در پوشهٔ `Theme/` حفظ شده است. نسخهٔ فعال سایت از همان HTML و CSS در `templates/core/` و `static/assets/` استفاده می‌کند. داده‌های اولیهٔ ۶ پروژه، ۱۲ مقاله و ۵ عضو تیم در زمان اجرای migration وارد SQLite می‌شوند.

## اجرای محلی

از پوشهٔ اصلی پروژه:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export DJANGO_DEBUG=1
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

- سایت: <http://127.0.0.1:8000/>
- پنل مدیریت: <http://127.0.0.1:8000/admin/>

اگر قبلاً کاربر مدیر ساخته‌اید، مرحلهٔ `createsuperuser` را دوباره لازم ندارید. دیتابیس محلی `db.sqlite3` همین حالا ایجاد و داده‌های اولیه در آن وارد شده‌اند؛ برای اجرای دوباره روی همین پوشه تنها `python manage.py runserver` کافی است.

## بخش‌های قابل مدیریت

- **پروژه‌ها:** عنوان، نشانی یکتا، دسته (تجاری، اداری، مسکونی یا سایر)، موقعیت، سال، متراژ، متن، تصویر اصلی، گالری، ترتیب نمایش و جایگاه صفحهٔ اصلی.
- **مقاله‌ها:** عنوان، نشانی یکتا، دسته، تاریخ شمسی، متن، تصویر، وضعیت انتشار و فایل دانلود اختیاری. دکمهٔ دانلود فقط برای مقاله‌ای نمایش داده می‌شود که فایل دارد. دسته‌بندی‌های مقاله در پنل قابل افزودن و حذف‌اند؛ پس از حذف یک دسته، مقاله‌های آن به «سایر» منتقل می‌شوند.
- **اعضای تیم:** نام، سمت، تصویر، ترتیب و وضعیت نمایش.
- **درخواست‌های مشاوره:** فرم صفحهٔ اصلی اطلاعات را با اعتبارسنجی سرور و CSRF در دیتابیس ثبت می‌کند. درخواست‌ها در پنل مدیریت دیده می‌شوند و می‌توانید وضعیت و یادداشت داخلی را تغییر دهید.
- **اطلاعات تماس سایت:** نشانی، تلفن و ایمیل فوتر از پنل مدیریت قابل ویرایش است. مقادیر اولیه از قالب آمده‌اند و ایمیل `.example` باید با ایمیل واقعی جایگزین شود.

برای افزودن تصویر جدید از فیلد «تصویر بارگذاری‌شده» استفاده کنید. تصویر بارگذاری‌شده بر «مسیر تصویر قالب» اولویت دارد. فایل‌های آپلودی در `media/` قرار می‌گیرند و هنگام اجرای محلی با `DEBUG=1` سرو می‌شوند.

متن پروژه و مقاله HTML است تا ساختار فعلی قالب (تیتر، نقل‌قول، فهرست و تصویر میان متن) حفظ شود. این فیلد فقط باید به مدیران مورد اعتماد دسترسی داشته باشد.

## آزمون

```bash
DJANGO_DEBUG=1 python manage.py check
DJANGO_DEBUG=1 python manage.py test
```

## آماده‌سازی برای استقرار

برای استقرار عمومی، `DJANGO_SECRET_KEY`، `DJANGO_DEBUG=False`، `DJANGO_ALLOWED_HOSTS`،
`DJANGO_CSRF_TRUSTED_ORIGINS` و متغیرهای `DB_NAME`، `DB_USER`، `DB_PASSWORD` را روی سرور
تنظیم کنید. در حالت production از PostgreSQL استفاده می‌شود. مقادیر `DB_HOST` و
`DB_PORT` در صورت نیاز قابل تنظیم‌اند و پیش‌فرضشان به‌ترتیب `127.0.0.1` و `5432` است.
فایل‌های static/media باید به‌وسیلهٔ وب‌سرور سرو شوند.

ریشهٔ همین پوشه، یعنی پوشه‌ای که `manage.py` و `requirements.txt` در آن قرار دارند،
ریشهٔ مخزن GitHub است. دیتابیس محلی `db.sqlite3`، محیط مجازی، فایل‌های `.env` و
تصاویر آپلودی `media/images/` در Git قرار نمی‌گیرند. داده‌های اولیهٔ عمومی با
migration ساخته می‌شوند؛ حساب مدیر محلی به سرور منتقل نمی‌شود.
